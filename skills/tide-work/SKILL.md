# tide-work — как агент работает с работой

Работа = арка `kind: work` в `.tide/arcs/works/NN-slug/work.md` того проекта,
где её завели — по умолчанию текущего (контрол-дом сам тоже tide-проект, его
работы лежат в его же `.tide/arcs/works/`): свободный текст (задача или
проблема, без типов) + `## план` + `## чеклист` + `## журнал`. Доска — проекция
этих файлов: коробочная `tide board` карточки показывает, кнопки человека есть
на живой (интерактивной) доске. Твоя механика — **родные вербы `tide work …`**
(закон «работа = вид арки»: не отдельная сущность, а арка со своей
стейт-машиной).

Стейт-машина: `open → taken → review → done`. Вербы сами двигают статус и
пишут журнал — руками work.md не правь. Ключ работы: NN, NN-slug или slug.
Работа лежит в ДРУГОМ проекте ростера → добавляй `--project <имя из ростера>`
к любому вербу.

## жесты

**0. Осмотреться.** `tide work list` / `tide work show <key>`.

**1. Разложить и согласовать — диктовкой.** План и шаги вешаешь ты, «да»
говорит человек — не кнопкой на карточке, а словами в чат оркестратора
(решение 06 нити: ответы человека только через сессию). Формат — «рамка
карточки» ниже.
```bash
tide work plan <key> "Проблема: …\nГде мы: …\nРезультат: …"
tide work propose <key> "Тайтл шага\nописание" "Второй шаг\nописание"
tide work propose <key> --replace "…"   # передумал: снять прежние [?], предложить эти
```
Предложенные пункты ложатся `- [?]` (на доске — пунктиром) и ждут слова.
Человек читает стол ISSUES и диктует: «ок / не ок / поправь». Фиксируешь
дословно:
```bash
tide work agree <key> --word "<его слово>"      # все висящие [?] → обычные пункты
tide work agree <key> 2 3 --word "…"            # только эти
tide work agree <key> --drop 4 --word "…"       # «нет»: пункт снят вместе с описанием
```
Согласовано → берёшь:
```bash
tide work take <key> --by <кто-ты> --word "<слово, которым взял>"
```
Предохранители (их не обходят, ими дожимают слово): `check`/`uncheck` по
`- [?]` отказывают; работа НЕ встанет в review, пока висит хоть одно `[?]`;
`propose` по работе в review вернёт её в taken — на столе снова вопрос.
`tide work checklist <key> …` — замена всего чеклиста уже согласованными
пунктами; по чекнутым откажет (`--force` только по слову человека).

**2. Работать.** Мир меняется в окне проекта из `project:` (его папку скажет
ростер), не там, где лежит карточка. Есть скилл проекта — сначала он.
`project:` пуст — спроси человека.

**3. Ставить курсор, когда берёшься за пункт.** Доска показывает, где ты
сейчас, ТОЛЬКО с твоих слов — сама она этого не знает и гадать ей запрещено
(«первый нечекнутый» уже врал человеку):
```bash
tide work at <key> <N>        # взялся за пункт N
tide work at <key> --clear    # отпустил, ни за что не взялся
```
Ставь при СТАРТЕ пункта, переставляй по ходу. Снимать после себя не надо:
`check` того же пункта снимает курсор сам. Курсор ничего не гейтит — это метка
«я тут»: от него доска подчёркивает пункт кобальтом и пишет строку «агент
делает: N · пункт». Курсора нет — строки нет вовсе, и человек видит только счёт.

**4. Чекать по факту.** Только сделанное, пруф обязателен (верб не пустит
без него):
```bash
tide work check <key> <N> --proof "что именно сделано: коммит/ссылка/файл"
tide work uncheck <key> <N> --reason "почему откатился"
```
**Чекает исполнитель** (подпись человека 30.07): пункт делал ты — ты и чекаешь, с
пруфом (без него верб не пустит). Пункт по природе человеческий — увидеть
глазами, запустить у себя, личное — чекает человек: кликом на живой доске (его
рука сама себе пруф, в журнал ляжет «рука человека»), а без неё — словом тебе,
и тогда чекаешь ты с пруфом «рука человека: <слово дословно>». Галочка при этом
НЕ приёмка: властные жесты человека — отдельные, это «да» на план
(`agree --word`) и закрытие (`close --word`; на живой доске — кнопка).

**Пруф начинается короткой строкой** (подпись человека 31.07, работа 33: «читаю —
очень сложно воспринимать; хочу быстро кликнуть и увидеть, что действительно
проверено»). Первая строка — человеку: что сделано, чем проверено, что осталось
непроверенным. До ~120 знаков, БЕЗ путей и номеров строк. Дальше пустая строка —
и ниже техника для протокола, сколько угодно: файлы, функции, команды, цифры.
```bash
tide work check 33 3 --proof "Что сделано — одной строкой, человеческим языком.
Проверено рендером на узком экране.

live_projection.py: _proof_split (~4860) режет по пустой строке…"
```
Эта первая строка — ЛИЦО пункта на карточке: она стоит под ним обычным тихим
текстом и видна БЕЗ клика (слова «пруф» на доске нет вовсе — решение человека 01.08). За
клик уходит только техника — свёрткой «детали». Пруф одной простынёй карточка
тоже покажет, порезав по первому предложению, но угадывать за тебя, где
кончается человеческое, она не должна: что попало в первую строку, то человек и
прочтёт, решая, принимать ли работу.

Все согласованные пункты чекнуты → верб САМ переведёт в review и скажет —
передай человеку словами: работа готова к закрытию.

**5. Накидка у приёмки → fix-пункт НЕМЕДЛЕННО.** Человек смотрит сделанное и
докидывает («номер на карточке», «пилюли мельче») — это не разговор, это новый
пункт работы. Вешаешь сразу, его слово и есть согласование: пунктира `[?]` тут
нет.
```bash
tide work fix <key> "Тайтл\nописание" --word "накидка дословно"
```
Пункт ложится в секцию `## фиксы`, нумерация сквозная с чеклистом, чекается как
обычный — с пруфом. Фикс по работе в review вернёт её в taken: пока он не
чекнут, работа не готова.

**6. done — НЕ твой жест.** Закрывает человек: скажет тебе словом — тогда
жест ниже (на живой доске есть и кнопка «закрыть»):
```bash
tide work close <key> --word "<его слово дословно>"   # слово ляжет в журнал
tide work reopen <key>                                # если открыть обратно
```

## рамка карточки (подпись человека 30.07)

**Карточка написана человеку** (подпись человека 01.08: «в будущем все работы
по-человечески должны быть сделаны»). Всё, что человек видит на карточке —
заголовок, план, шаги с описаниями, пруфы, вопросы — его языком, теми словами,
которыми он сам про эту работу говорит. Имён файлов, функций и номеров строк
в том, что он читает, нет: по ним не решают, по ним отчитываются. Техника не
пропадает, она уходит вглубь — за первую строку пруфа (жест 4) и в тело
описаний; наверху остаётся то, по чему человек решает: сделано или нет, годится
или нет. Проверка на слух: прочитай написанное вслух — понял бы он, не открывая
репозиторий? Нет — переписывай. Правила ниже — частные случаи этого одного.

- **Заголовок — ИМЯ работы** (подпись человека 31.07): 2–4 слова, звонко —
  глагол или ярлык («Переезд на новый сервер», «Гигиена субагентов», «Нить видит
  свои работы»). Без двоеточий и перечислений — вторая голова и фазы уезжают
  в план. Простыня в H1 — боль: карточка не читается. Детали живут в плане и
  описаниях шагов. Переименование — только со словом человека:
  `tide work title <key> "<новый>" --word "…"`.
- **План — три строки: Проблема → Где мы → Результат**, Результат последней.
  Образец: «Проблема: доску не открыть с телефона. Где мы: сервер слушает
  только localhost. Результат: доска открывается с телефона в два жеста».
- **Шаг — «Тайтл\nописание»**: первая строка — действие, как в тетради;
  подробности ниже, отдельным абзацем.

## стол ISSUES — где читает человек

Первая вкладка живой доски: только то, что ждёт его руки (согласования и работы в
review), и **одно целевое действие сверху**, остальное свёрнуто. Отсюда
правило: не вешай несколько согласований разом — лишние уедут в свёрнутое, а
человек утонет. Одно предложение → слово → следующее.

## ответственная нить — привязывает/отвязывает АГЕНТ (не человек)

Владение нитью ведёшь ТЫ, руками человек это не делает (его слово 17.07):
- **привязка — авто:** `tide work take` (1.0.43) записывает ответственную
  нить сам — ту, в чьей сессии ты сидишь (резолв по `$CLAUDE_CODE_SESSION_ID`
  → арка → нить). Из чужого проекта — адресом `proj/NN-@нить`.
- **отвязка — тоже твой жест:** перестал вести работу (передал хендоффом,
  освободил) → `tide work thread <key> --clear`. Сменить нить —
  `tide work thread <key> --set <NN-@нить>`.

Связь двусторонняя на живой доске: ВЕДУЩИЙ агент и кнопка «провалиться →» (возврат в
его сессию) живут на большой карточке вкладки «работа» и на карточке стола
ISSUES — это два входа в сессию работы с доски; ручного селекта нити нет
(владение создаёт только агент). Компакты — в детали нити и на полке проекта
(вкладка «работы», во всю строку) — с работы 26 только читаются: имя, состояние
и ход, кнопок на них нет, клик → модалка. Контеншн-лока пока нет: если возьмёшь работу, уже ведомую
другой нитью, — просто перезапишешь; аккуратнее (человек отложил жёсткий лок).

## правила

- **Мир меняется только под работой** (подпись человека 31.07): билд-воркер не
  диспатчится без взятой карточки — в задании воркеру ключ работы и строка
  «трение → кандидат сразу»; накидка по ходу = `fix` в ту же работу; карточки
  нет — сначала заведи и согласуй. Чтение, разведка, разговор — можно без
  карточки: мир не меняют.
- **Отправил строителя — отметь** (урок 01.08, кандидаты 179/180): оркестратор
  взял работу 35, доложил человеку и писал в пульсы «у воркера», а сообщения
  воркеру не отправил — три часа карточка выглядела живой, стройки не было.
  Очередь отправок в голове не живёт:
  ```bash
  tide work dispatch <NN | NN-slug | slug> --to "<имя воркера>"
  ```
  Строка ложится в журнал работы, статус НЕ двигается (отправка — событие, а не
  состояние), повторная отправка — просто ещё одна строка: воркера переотправили,
  сменили, добавили второго. Шлётся только на взятую: диспатч на `open` — дырка
  цикла, плана ещё нет и «да» не сказано.
- **Трение → кандидат сразу** (решение 08 нити 25-@edinyy-sloy, 31.07): наткнулся
  на проблему — замедление, грабли, момент, где человек вскипел — роняешь её тем
  же ходом, не дожидаясь конца работы и не разбираясь на месте:
  ```bash
  tide candidate add <slug> "<вся ситуация: что делал, где споткнулся, чем кончилось>"
  ```
  Трение про другой проект ростера → `--project <имя>`, ситуация целиком в
  тексте (откуда пришла — тоже); про сам tide → ещё и `tide report "<та же
  история>"` — боль уедет автору. Правило одно для воркера и для оркестратора:
  разбор потом, из кандидатов; молча остаться с проблемой нельзя.
- **Кандидат ушёл в работу — уходит с полки** (слово человека 01.08: «если кандидат
  переходит в работу, то он сразу должен выбрасываться, чтоб не дублировалось»).
  Не два жеста на твоей памяти, а один верб — роди работу прямо из кандидата:
  ```bash
  tide work add "Имя 2–4 слова" --cand <NN | NN-slug | slug>
  ```
  Текст кандидата ляжет ЧЕРНОВИКОМ в `## план`, сам он уедет в `__dropped__`
  (тем же путём, что крестик на доске: с полки, но не с диска), в журнале —
  «рождена из кандидата». Имя работы всё равно из аргумента: слаг кандидата
  длинный, тайтлом не годится. Ничего это не обходит — работа рождается `open`
  и проходит plan → propose → «да» человека, как любая другая. Родилась мимо
  верба — выброси кандидата рукой тем же ходом и назови его номер в плане.
  Полка, дублирующая стол, обещает человеку то, что уже делается: 01.08 таких
  выбрасывали руками задним числом.
- **Забор проверяют манекеном, а не собой** (урок 31.07, кандидат 166): надо
  узнать, как ролевой гейт порежет команду — спрашивай движок, а не живой шелл:
  ```bash
  tide hook role-gate --explain-file /tmp/proba.txt   # опасную строку держи в файле
  tide hook role-gate --explain 'ls | head -3'        # инлайн — только для безобидной
  ```
  Печатает вердикт, какое звено срезано и каким правилом, и не исполняет ничего.
  Гонять пробы через настоящий Bash нельзя: так воркер и проверял гейт 31.07 —
  `$(rm -rf .)` раскрылось по-настоящему, дерево уцелело случайно. Воркер не
  загейчен, ловить некому — держится на этой привычке.
- Дописывать пункты после согласования — только новым `propose` и новым словом;
  накидка у приёмки — сразу `fix` (тоже со словом).
- **Пункт — на единицу результата** (фикс, шаг), а не на воркера. Двое строили,
  третий проверял — это ОДИН пункт; кто строил и чем проверено, живёт в его
  пруфе: «сделано таким-то, проверено сквозняком».
- Ответы человека приходят ТОЛЬКО из сессии; кнопки «да» на карточке нет —
  не жди клика, спроси в чате. **Спросил, а он ушёл или молчит** — вопрос не
  оставляют тонуть в скролле, он ложится вещью на стол:
  ```bash
  tide artifact add "<подпись: чего ты ждёшь>" --ask "<вопрос целиком>" --work <NN>
  ```
  Ляжет `kind: question` — карточка ждёт его на столе ISSUES и ведёт в твою
  сессию; отвечает он всё так же словом (не кнопкой). Кнопок на карточке
  вопроса нет вовсе (слово человека 01.08): ни звезды, ни «ответил ✓» — только текст и
  ход в сессию. Значит, УБИРАЕШЬ ЕЁ ТЫ, услышав ответ, и сразу:
  ```bash
  tide artifact taken <NN> --word "<его ответ дословно>"
  ```
  Не уберёшь — стол будет звать к вопросу, на который уже ответили, а этому
  человек верить перестанет. Из чужого проекта — `--project <имя из ростера>`. Так
  же кладут гейт плана, в который ты упёрся: доске не надо гадать, кто чего
  ждёт.
- Дедлайн сегодня/просрочен — скажи человеку сразу, не молчи.
- Название, дедлайн и project без слова человека не менять.
- У человека на живой доске свои жесты (чек, правка текста кликом, закрыть/открыть,
  нить, дедлайн) — файл всегда прав, перед своим жестом глянь `show` свежим
  глазом.

  пункт `check --proof` по мере готовности. Работает: план виден на доске,
  прогресс живой. Так и делай крупную работу — планом через свой же цикл.
