КАК ВСЁ РАБОТАЕТ ВМЕСТЕ

Три вещи, три срока жизни. НИТЬ живёт месяцами — это перспектива: цель, то, что нельзя забыть, решения, работы. СЕССИЯ живёт часами — один агент в одном терминале и список того, что он сделал. АКТ живёт мгновение — одна строка: что сделано, с пруфом.

Агент пишет акты. Нить читается из них обратно. Ты меняешь нить рукой — «да», «готово», решение. Вот и вся машина; остальная страница — про то, где живёт каждая часть и какая команда её трогает.

English — how it works together.

ОДНА КАРТИНКА

   ТЫ   ── терминал: «посмотри», «передай нить» ──▶  СЕССИЯ
    ▲     доска: стол · нити · работы · решения         │
    │                                                   │  акты, через tide CLI
    │   твоё слово: да · готово · решение               ▼
    └───────────────────────────────────────────────  НИТЬ
                                    цель · главное · решения · работы · сессии

Жёсткие правила сидят на CLI хуками; мягкие — в промпте, и они короткие.

НИТЬ

Нить — это папка: .tide/arcs/NN-@name/. Внутри — plan.md с целью и секцией ГЛАВНОЕ, которая печатается раньше всего остального, decisions.md и arcs/ — по паспорту на сессию. Работы лежат рядом, в .tide/arcs/works/.

tide thread                     # вся нить на одном экране
tide thread --check             # что горит: обещания без работы, молчащие арки

Увидишь сначала ГЛАВНОЕ, потом план и его открытые шаги, решения в силе и какая работа несёт каждое, где стоит ведущая сессия, работы в ходу, что ждёт твоей руки, и сессии — новые сверху.

СЕССИЯ

У каждой сессии есть паспорт, arcs/NN-slug/arc.md: роль, курсор и строки пульса. Нить ведёт новейшая принятая сессия; прошлые остаются открытой историей, в которую можно вернуться. Пульс — это десять секунд, а не отчёт:

tide offload <arc> --cursor "что делаю сейчас" --next "шаг · шаг" "что сделал"

Без пульса доска слепа — хук подталкивает сессию, которая замолчала.

АКТ

Сегодня у акта три формы, и каждая — одна строка с отметкой времени в журнале: пульс, чекнутый пункт, диспатч.

tide offload <arc> "нашёл ответ — лежит в workspace/notes.md"
tide work check 12 3 --proof "запустил — отвечает"         # без пруфа не чекнется
tide work dispatch 12 --to "builder"                       # отправлен воркер

tide work show 12 печатает журнал работы: каждый жест строкой, с твоими словами внутри.

ТИК

Цикл агента — два шага: прочитать, потом сделать.

tide thread                                  # где я
...делается одна вещь...
tide work check 12 3 --proof "..."           # или пульс

В разговоре не остаётся ничего, что понадобится следующей сессии — если это важно, это акт.

КАК ДУМАЕТ АГЕНТ

Сессия — это Claude Code, а вокруг него tide. По порядку, от пробуждения до передачи:

  1. ПРОСЫПАЕТСЯ ОТ СПАРКА — tide menu или tide go открывает терминал, где Claude Code уже в контексте; сид хендоффа, если он висит на нити, — первое, что он читает. Стартовый хук печатает статус: нити, кандидаты, что не прочитано.
  2. ПОЛУЧАЕТ ПРОМПТ СЛОЯМИ — свой от Claude Code, потом роль (голова или воркер), канон проекта из .claude/rules/, план нити с MAIN впереди и сид. Это мягкие правила; они нарочно короткие.
  3. ЧИТАЕТ ОДИН ЭКРАН — tide thread. Потом tide work show для той одной работы, к которой сейчас прикоснётся, — не для всех.
  4. ГОВОРИТ, ПОТОМ ДЕЙСТВУЕТ ЧЕРЕЗ CLI — твои слова приходят в терминал; каждое изменение, которое агент вносит в нить, уходит командой: пульс, чек с пруфом, диспатч, кандидат, решение. Вызов виден, и на него можно посадить хук.
  5. ПОЛЬЗУЕТСЯ ДРУГИМИ РУКАМИ — скиллы и MCP-серверы (браузер, трекер, календарь) — родные для Claude Code; tide их не оборачивает. Что из них вышло, ложится в нить актом или файлом.
  6. ВЫГРУЖАЕТСЯ ПО РИТМУ — пульс на каждом повороте или решении; хук подталкивает после пятнадцати минут тишины.
  7. ОТПРАВЛЯЕТ ВОРКЕРОВ — с полными руками, в workspace нити; диспатч — строка в журнале работы, результат — файл.
  8. ПЕРЕДАЁТ — tide handoff сворачивает сессию в сид; следующая сессия принимает его и пульсирует. Или вовсе без сида: когда акты записаны, нити достаточно.
tide thread                                  # один экран
tide offload <arc> --cursor "..." --next "..."   # пульс, по ритму
tide work check 12 3 --proof "..."           # акт, через CLI
tide handoff                                 # сид для следующей

Здесь нет ничего, что агент должен помнить как фичу. Голова не может править файлы, чек отказывает без пруфа, тишина получает толчок — рельсы это хуки, и промпт остаётся про работу.

ГОЛОВА И ВОРКЕРЫ

Сессия, с которой ты говоришь, — голова. Она читает, разговаривает и ходит tide; гейт роли не даёт ей править файлы самой. Она отправляет воркеров с полными руками, и каждый диспатч — строка в журнале работы. Воркер кладёт находки файлом в workspace нити; голова чекает пункт с этим путём как пруфом — «готово» это файл, а не рассказ о нём.

ГЕЙТЫ

Жёсткие правила — хуки на CLI, а не фразы в промпте:

  1. чеку нужен пруф — без него верб отказывает
  2. done ставит только твоя рука — tide work close --word "…" или кнопка на живой доске
  3. голова не правит файлы — она диспатчит
  4. замолчавшую сессию подталкивают к пульсу

Мягкие правила — канон, роль, нить — едут в системном промпте и держатся короткими, чтобы агент был в работе, а не в своде правил.

ХЕНДОФФ

Хендофф сворачивает сессию в сид и вешает его на нить; ничей терминал сам не открывается. Следующая сессия принимает его тремя жестами:

tide handoff                    # из старой сессии: сид на нити
tide handoffs take              # из новой: принять
tide offload <arc> ...           # первый пульс — гейт закрыт

Сид — это вход. Память — это нить. В тесте одну работу пронесли через пять хендоффов; на двух швах сида не было вовсе — сессии восстановили картину из плана нити, решений и журналов, и ничего не потерялось.

ДОСКА

tide board --open               # http://127.0.0.1:8765

Одна страница: стол входящих — только то, что ждёт твоей руки, — потом нити с их сессиями, работами, решениями. Твоих жестов немного: «да» плану, «готово» работе, решение. Всё остальное делает агент, а ты видишь это там.
