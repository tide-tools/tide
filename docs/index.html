§ 01

Three ways the work leaks away.

You're not slow. The tools are leaking the work faster than you can do it. Three leaks, every project, every week.

01 / amnesia
Context dies between sessions
You open a fresh chat and re-explain the whole project from scratch — where things are, what you decided, why. The thread you built yesterday is gone. You pay the briefing tax again, and again.
02 / plumbing
Plumbing eats your attention
Spawning terminals, tracking what's open, remembering to merge notes — the coordination overhead consumes the one thing that's actually scarce: your judgment. You babysit the machine instead of steering it.
03 / scatter
Work never becomes truth
Decisions live in chat scrollback. A finished task leaves no durable trace. Two weeks later nobody — not you, not an agent — can answer "what is true about this project right now?" It scattered and it's gone.
tide's answer
→ State lives in files, not in a chat. Everything is plain markdown under .tide/ — cat, grep, diff it. A session starts empty and re-hydrates by reading. The thread is never lost.
→ Work runs in threads, and a thread outlives its sessions. Inside a thread, one session sits down, works, hands off to the next. The chat ends; the thread doesn't.
→ Your word is spent only where it's irreplaceable. A work is one card you and the agent agree on: the agent proposes steps and checks them off only with proof; done is set by you, in a word.
→ One view from above. tide board serves a page on localhost with the stream of your home and of every project — and the work cards on it.
§ 02

One real run, end to end.

The exact route of the first hour, shown once so you see the cycle with your own hands. In live work the agent in a session runs these; you steer in prose.

1
Home

One folder you lead everything from

The control-home holds the roster of your projects and its own .tide/ — tide leads itself the same way. Claude hooks and skills land by themselves: an agent opened in this home can hand off the thread and offload from day one.

~/tide-home · tide init
$ mkdir ~/tide-home && cd ~/tide-home $ tide init --git + roster.md · canon/CANON.md · .tide/ · plugins (core only) + git repo (birth commit) + Claude hooks · skills: handoff, offload, tide-flow ✓ tide control-home ready
2
Adopt

Projects live where they live

Any folder with code, old or new. tide adopt lays the .tide/ layer on top, seeds the canon with your goal, generates a README that speaks it, and writes the project into the home's roster. tide commits nothing into your working repo.

~/code/myapp · tide adopt
$ cd ~/code/myapp $ tide adopt --goal "a small web app — trying tide" ✓ tide scaffolded .tide/ (canon seeded with the goal) ✓ readme README.md generated from canon ✓ roster rostered → ~/tide-home ready: tide menu → myapp
3
See

The board — home and every project on one page

A page on localhost: a stream per project, a HEALTH line on each, work cards when the work surface is on. No database, no cache — it rebuilds the projection from .tide/ on every request, and re-reads every 30 seconds. What's in the files is what's on screen.

the view from above · tide board
$ tide board --open → serving http://127.0.0.1:8765 · localhost only streams: tide-home · myapp HEALTH on each

Phone too. The server stays on localhost; tailscale serve carries the board to your phone — two commands, in docs/board.md, next to the launchd recipe that keeps the board alive on its own.

4
Agree

A work — driven to closed, with proofs

A work is the agreement card between you and the agent: free text, a checklist, one deadline, a journal where every gesture is a line. The agent proposes and checks only with proof; done is set only by a human. Switch the surface on once per home, then watch one card cross the whole state machine.

open → taken → review → done
$ tide plugins on work $ tide work add "the app greets — check it runs" $ tide work propose 01 "run the app and see the answer" $ tide work agree 01 --word "yes" # your word $ tide work take 01 --by "first session" $ tide work check 01 1 --proof "ran it — it answers" $ tide work close 01 --word "accepted" # done: human only ✓ done — the journal holds every gesture, with your words
5
Talk

From here on — words, not commands

tide menu picks a project, then a thread, and opens a terminal with Claude already in context: role, the project's canon, the active thread, the roster. You say what you want — "start a work: …", "hand off the thread", "show status" — and the agent walks the verbs from step 4 itself. This step needs Claude Code; the tide mechanics work without it.

~/tide-home · tide menu
$ cd ~/tide-home $ tide menu project › myapp thread › + new thread → terminal opens · Claude seeded: role, canon, thread, roster you › start a work: greet users on first launch

Full permissions by default. Sessions from tide menu open with tool confirmations skipped — a deliberate default for the interactive head; tide menu --no-skip-permissions brings the prompts back.

session A──╮
　　　　　╰─ handoff ─╮
session B ─ close ─→ work · done

The thread crossed two sessions and the work closed with proofs and your word. Nothing was re-explained. Nothing scattered. The board saw every move — in files you can read.

§ 03

What the one binary gives you.

Namespaced subcommands that compose the way git <verb> does. Honest and concrete — every one is real. The full tree: tide help.

§ 04

Built like a small UNIX tool, on purpose.

One binary tide adopt …, tide work …, tide board — namespaced verbs that compose like git. No platform to host, just the point you lead from.
Plain text is the DB Everything is markdown under <project>/.tide/. No database, no cache: even the board rebuilds its projection from the files on every request. cat, grep, diff and git just work on your state.
You steer in words The agent in a session doesn't memorize commands — you say what you want, it walks the tide verbs. You never type the inner verbs by hand.
A layer, not a takeover tide commits nothing into your working repo: .tide/ just sits next to the code, and tracking or ignoring it is your call. The package is depersonalized — skills speak in roles, not names.
Dogfooded tide is led as a tide project, in its own .tide/. The machine runs itself.
§ 05

Install — the whole path, on this page.

Requires Python ≥ 3.12. Everything below takes you from zero to a living board; sessions (tide menu) also need Claude Code — the tide mechanics work without it.

01 · The main door
Clone and one command. install.sh puts tide on your PATH — pipx if you have it, its own venv + symlink otherwise — and says the next gesture. The source stays with you, on purpose.
$ git clone https://github.com/tide-tools/tide && cd tide $ ./install.sh # ✓ tide <version> — and a hint at the next gesture
02 · Homebrew — binary only
The second channel: carries just the binary — the skills, hooks and board travel with the clone. Fine for later.
$ brew tap tide-tools/tide https://github.com/tide-tools/homebrew-tide $ brew install tide-tools/tide/tide
03 · Unfold a home
One folder you lead everything from. Claude hooks and skills land by themselves. Add the export to your shell profile so tide finds the home from any folder.
$ mkdir ~/tide-home && cd ~/tide-home $ tide init --git $ export TIDE_HOME=~/tide-home
04 · Adopt a project
Any folder with code, old or new. It is born speaking: its README and canon carry your goal, and the home's roster already holds it.
$ cd ~/code/myapp $ tide adopt --goal "a small web app — trying tide"
05 · Open the board
Home and every project on one page, re-read from .tide/ every 30 seconds. The server listens on localhost only; tailscale carries it to your phone — that, and the launchd service, in docs/board.md.
$ tide board --open # http://127.0.0.1:8765 $ tailscale serve --bg 8765 # the same board on your phone — HTTPS, your tailnet only
06 · Update · fix · report
It tells you itself when a fresh release is out. Broke something? The source is already yours — fix it, reinstall in place, send the pain upstream.
$ tide self-update # git pull + reinstall — gated, with rollback $ ./install.sh # fixed the source? reinstall in place $ tide report "what happened" # lands as a gh-issue or a file · home paths scrubbed

From here it's words: cd ~/tide-home → tide menu opens a seeded Claude session — you talk, the agent walks the verbs. The first hour, step by step: QUICKSTART.md. The full command tree: tide help.
