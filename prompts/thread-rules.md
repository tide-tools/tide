# Правила нити tide

Одно место правил работы в нити (SOC-181). Сид передачи, сид запуска `tide go`,
`prompts/orchestrator.md`, `prompts/worker.md` и `rules/subagents.md` ссылаются сюда,
а не копируют. Правится только этот файл; пороги `tide escalate` в коде
(`tide.escalate_rules`) сверяет с ним тест.

- работа: файлы — в workspace/ своей арки, итог — в output/; пульс по ходу — tide offload; передать дальше — /handoff
- итог сабагента — «сделано · пруф · что не охвачено», не длиннее ~600 токенов (~2000 знаков); подробности — файлом в workspace/ своей арки, в итоге — путь к файлу
- тесты: сабагент не ждёт прогон дольше ~4,5 мин в одном вызове — долгие (полный tide-ci) в фоне (Bash run_in_background), проверка по готовности
- почта: ao send между сессиями — только сигнал: 1–2 строки + «письмо NNN в почте нити»; текст — tide mail send <проект>/<нить>; несрочное — пингом пачкой до 25 мин, срочное — --urgent
- троттлинг: перед новым сабагентом или тяжёлым прогоном — tide throttle status; на паузе новые сабагенты не запускай, доведи шаг до коммита; потолок агентов достигнут — жди; окно ≥85% — только точечные тесты
- модели: рутина помощников — model: sonnet (поиск, чтение, Explore, прогоны, смоук, сводки); код и ревью — Opus; долгие прогоны в фоне, проверка кусками ≤4 мин
- веер сабагентов: не больше 3 одновременно и 8 за задачу; поручение — «что сделать · где · критерий готовности · формат ответа»; по умолчанию сабагент на Sonnet (CLAUDE_CODE_SUBAGENT_MODEL=sonnet), Opus — только явно, для кода и ревью; превышение ловит мягкое предупреждение хука subagent-budget
- отчёт: по готовности работы (итог задачи, In Review, конец цикла, хендофф) — tide work-report --done … --proof … --next … --waits … --soc SOC-N: сделано с пруфом · дальше · ждёт пользователя; уходит в TG-тему проекта и ленту «Отчёты» на доске
- режимы: лид проекта и менеджер — разговор с пользователем (хендофф предлагай пользователю с 200 тыс., принудительный с 350; в паспорте auto-handoff: off = менеджер); исполнитель — автономный цикл: одна задача SOC-N, оценка в % квоты, срок, «готово когда», автохендофф (спокойный момент с 150 тыс., обязательно с 200, тревога менеджеру с 300); по концу — отчёт (tide work-report) и In Review
- план цикла: шаги (что · где — абсолютные пути, файлы, функции · готово когда шага) · оценка в % квоты · готово когда · не делать · проверка вживую; разведку делает планировщик один раз, исполнитель идёт по плану; без плана tide cycle start отказывает (--plan ссылка на план, --steps, --not-do, --check, --estimate, --done-when); в цикле курсор держит правило мяча — пауза цикла на пользователе (tide cycle end --status user) только с открытым вопросом TG N
- лимит: лимитов квоты по проектам нет — есть работа, делай; единственная рамка — цель пользователя «к времени X осталось Y» (SOC-219); расход выше оценки цикла не стоп, а событие менеджеру
- вопрос пользователю: нужен его выбор — сразу вопрос во «Вопросы» доски через пульт (tg-alert, адрес human): ❓, «Почему:» 1–3 строки, «варианты: ⭐ рекомендуемый первым …»; не держать в окне и не копить (❓ строкой в окне никуда не попадает); в личку Telegram вопросы и эхо «✓ с доски» не дублировать — только доска (слово пользователя 12.10); после вопроса не ждать — продолжай по ⭐ или бери следующее, ответ придёт — поправишь; ждать ответа обязательно только для необратимого или наружу (выкат игрокам, публикация, сообщения людям, деньги, удаление) — тогда мяч у пользователя; переспрос пользователя на вопрос — уточнение: ответь, вопрос остаётся открытым
- мяч: у каждой сессии курсор (tide offload --cursor) — одно из четырёх: «мяч у меня: задача + срок» (SOC-N или работа N и HH:MM или --eta) · «мяч у пользователя: вопрос TG N» (открытый вопрос во «Вопросах») · «мяч у <роль/сессия>: что ждём · письмо N» (менеджер, main, нить; письмо ей уже ушло; срока нет — «мяч у менеджера: ок на поправки · письмо 459»; без адресата, «что ждём» или номера письма это голое «жду») · «отдых по слову пользователя»; «жду/ждёт» без открытого вопроса — нарушение, его ловит Stop-хук offload-nudge и требует выставить вопрос или взять работу; ждать отчёт своего помощника, письмо другой сессии или прогон законно как «мяч у меня» с задачей и сроком («мяч у меня: SOC-240, жду отчёт помощника к 03:30»)
- дела пользователя: шаг, который делает он сам (нажать, ввести пароль, написать человеку), — делом на доске через tg-alert: ☐ (сделать) или 🖐 (нужны его руки у экрана): что именно сделать, ссылка, «Почему:»; не строкой «ждёт тебя» в отчёте
- ответ пользователю: за ≤5 мин — менеджер или диспетчер сразу отвечает строкой (принял · что будет · когда), работа — после
- файл человеку (SOC-249): упомянул файл в сообщении человеку — приложи его: tg-alert --file <абсолютный путь> (можно несколько; картинка уйдёт фото, остальное документом, в ту же тему); путь без вложения с телефона не открыть, tg-alert при пути без --file предупреждает в stderr
- опыт: наступил на граблю — сразу tide thread layer --exp "…", не ждать передачи
- не справляешься — tide escalate --what … --tried … --need …: 2 неудачные попытки одного шага, или стоп дольше 30 мин без прогресса (ждать ответа пользователя на открытый вопрос TG N или менеджера по правилу мяча — не застревание), или задача вне твоей роли/прав (отказ role-gate — отдай сабагенту, это не повод); письмо уйдёт main проекта, без квитанции 30 мин — менеджеру; закрыть — tide escalate --close NNN --word "чем"
